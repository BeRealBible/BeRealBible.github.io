# 经文问答

- 界面功能：经文问答。单条数据：问答条目（QAP）。
- 经文锚点：`[书卷代码, 章]`（整章）或 `[书卷代码, 章, 起节, 止节]`。跨章段拆到各章；跨卷、各处平行经文保存在同一条的多个锚点。按经节匹配真实重叠，不填充用户没有选的空档。选章号匹配本章的全部锚点；段落小标题不是锚点。
- `data/study-qa.json` 是生成的问答库。来源是 `LLM_QT` 正式目录中的编号书卷文件，只导入能识别的问答对。备份、模型对照、跑批包装和原稿路径不是发布数据。不要手改生成库，也不要覆盖 Obsidian 原稿。
- 更新用 `python tools/import-study-qa.py <LLM_QT目录> --audit <本机审计输出路径>`。默认每题只绑定来源章的一个对象：题干明确指出一段简短、连续的本章经文时挂该段；缺失、宽泛、多个分散地址或无法可靠定位时挂来源章。不得因题干／答文提到别处而逐章挂载；例如“族长史（12–50 章）”不是 39 个问答绑定。审计文件仅本地使用，用于检查孤立标题、无效坐标、绑定分布和编号。
- 已审阅的问答以 `tools/study-qa-primary/<书卷代码>.json` 为准，《列王纪上》为首批。每条保留实际讨论范围 `primary`；旁证和背景不产生挂载，但正文经文链接照常识别。只有问题确实同时讨论多处经文时才标多个主范围；问答来源章不必是挂载章。
- 已审阅的 `primary` 投影为发布库里的 `refs`。新增的 `"display":"exact"` 逐段保留审阅的真实范围，不把证据地址算进去；《列王纪上》的既有紧凑规则不变（按章计算：1–3 节保留，4–10 节挂起始节，11 节及以上挂章）。使用 `python tools/import-study-qa.py --apply-primary` 可只重建全库绑定，不重导题干和答案；`--check` 可防导入产物过时。审阅文件的 `textSha256` 对按 ID 字符串排序、紧凑 UTF-8 JSON 序列化的 `[[ID,题干,答案],…]` 校验，正文变化时先复核坐标，不静默沿用。
- 更改数据后运行 `node tools/stamp-preview.cjs . --index-only`，并验证 `python tools/test-import-study-qa.py`、`node test-v25-study-qa.cjs` 和问答浏览器测试。
- 纸本大章号和经文窗内的「第 X 章」支持长按选整章；段落小标题不接受选文手势或显示提示线。有匹配问答的经节或章号可显示提示线，提示线只受本机设置控制，不影响选择和查看。发布时由问答库生成轻量坐标索引；按钮置灰和提示线都同步使用它，只有打开问答才载入正文。
- QAP 正文按问答条目的来源卷章调用独立的 `V25CitationLinks`（识别／渲染）与 `V25ScriptureWindows.openCitation`（显示经文）。将来的笔记或其他浮窗可以同样传入正文和卷章上下文，无需提供问答条目或加载问答库。
- 问答通过 `V25ScriptureWindows.openStudy` 使用已有的固定浮窗与纸签槽位；相同选择只唤回原窗。每窗的答案开合和滚动状态各自保存。引用的固定操作不移除问答窗。
